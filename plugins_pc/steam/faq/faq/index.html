FAQ

This page covers common questions and troubleshooting topics related to Steam initialization, testing, Multiplayer, Lobbies, Voice Chat, Steam Input, player data, DLC, Rich Presence, and the Steam Publishing Tool.

For initial setup, see Getting Started. For feature-specific workflows, see the corresponding pages under Steam Features.

Installation and Initialization

Steam does not initialize

Check the following:

  • the Steam client is running
  • the current user is signed in to Steam
  • the correct Steam App ID is configured under: Edit → Project Settings → Plugins → PloxTools: Steam Integration
  • Enable Steam In Editor is enabled when testing from the Unreal Editor
  • Unreal Engine was restarted after changing the Steam App ID or Enable Steam In Editor
  • conflicting Steam integrations are disabled

You can verify the current state with Is Steam Initialized.

If Steam still does not initialize, test the project in a packaged build launched through Steam.

Can I use Steam App ID 480?

Yes.

App ID 480 is Steam's public Spacewar test application and can be used for early integration testing.

It is useful for checking whether Steam initializes and whether basic Steamworks functionality is available before your own Steamworks application is fully configured.

However, app-specific Steam data such as achievements, leaderboards, Cloud files, and other application data belongs to Spacewar while App ID 480 is being used.

For normal development and release testing, use the App ID of your own Steamworks application.

Steam works in a packaged build but not in PIE

Check Enable Steam In Editor under:

Edit → Project Settings → Plugins → PloxTools: Steam Integration → Development

This setting must be enabled for Steam to initialize when the game is launched from the Unreal Editor, including PIE and Standalone Game.

After changing this setting, restart Unreal Engine before testing again.

Packaged builds are not affected by Enable Steam In Editor.

Do I need Online Subsystem Steam?

No.

PloxTools: Steam Integration communicates with Steamworks directly and does not require Unreal Engine's Online Subsystem Steam.

To avoid conflicts, disable Unreal Engine Steam plugins that independently initialize or manage the same Steamworks systems.

Which built-in Unreal Engine Steam plugins should be disabled?

The following built-in Steam integrations should normally be disabled when using PloxTools: Steam Integration:

  • Online Subsystem Steam
  • Steam Shared Module
  • Steam Controller
  • Steam Sockets

Steam Audio is unrelated and can remain enabled.

Can I use another Steam plugin together with PloxTools: Steam Integration?

Possibly.

A separate plugin can coexist if it does not independently initialize or manage the same Steamworks systems.

Plugins that initialize Steamworks themselves, replace Steam networking, or manage the same Steam interfaces may conflict with this plugin.

If unexpected Steam initialization or networking behavior occurs, disable the other Steam integration and test again.

Why do I need to restart Unreal Engine after changing the Steam App ID?

The Steam App ID and Enable Steam In Editor setting are read when the Steam module starts.

Changing either value while the Editor is already running does not reinitialize the Steam module with the new configuration.

Restart Unreal Engine before testing the new values.

Testing

What is the best way to test Steam features?

Different environments are useful for different kinds of testing.

PIE is useful for:

  • quick Blueprint or C++ API checks
  • callbacks
  • achievements
  • stats
  • basic user data
  • basic Steam state checks

Standalone Game is preferable for:

  • Steam Overlay
  • window focus behavior
  • networking
  • testing in a more independent game context

A packaged build launched through Steam is the most reliable environment for final testing, especially for:

  • Multiplayer
  • Voice Chat
  • map travel
  • Steam Overlay
  • Cloud Saves
  • Rich Presence
  • DLC
  • Steam Input
  • release behavior

Why does the Steam Overlay not open in PIE?

Steam Overlay behavior depends on how the game process and window are launched.

PIE runs inside the Unreal Editor environment and is not always representative of a normal Steam-launched game.

If Overlay behavior is inconsistent, test using Standalone Game or, preferably, a packaged build launched through Steam.

Why does Multiplayer Travel not work correctly in PIE?

Unreal Editor multiplayer and world travel behavior can differ from a packaged game.

For this reason, Travel Steam Game is best tested in a packaged build launched through Steam.

PIE can be useful for basic multiplayer development, but it should not be treated as the final validation environment for travel behavior.

Can I test multiplayer with multiple players on one Steam account?

For reliable Steam multiplayer and social testing, use separate Steam accounts where the Steam feature requires separate users.

Testing multiple local game instances under the same Steam account does not represent a normal real-world multiplayer environment and may produce misleading results.

Final multiplayer testing should use packaged builds and separate Steam accounts.

Should I use App ID 480 for final multiplayer testing?

No.

Spacewar is useful for early validation, but final multiplayer testing should use your own application's App ID.

This ensures that your lobby data, Rich Presence, networking behavior, permissions, and Steamworks configuration match the application that will actually be released.

Lobbies and Multiplayer

What is the difference between Lobbies and Multiplayer?

The Lobbies feature is a low-level Steam lobby API.

It is used for:

  • creating and joining Steam lobbies
  • searching for lobbies
  • lobby data
  • member data
  • lobby membership
  • invitations
  • lobby events

The Multiplayer feature is a higher-level managed system.

It handles the complete flow around:

  • creating or reusing a Steam lobby
  • starting an Unreal listen server
  • finding compatible games
  • joining the host
  • Steam networking
  • travel
  • connection state
  • multiplayer lifecycle events

Use Lobbies when you want to build and control the lobby flow yourself.

Use Multiplayer when you want the plugin to manage the actual Steam multiplayer connection flow.

Does creating a Steam Lobby connect players to the Unreal game?

No.

A Steam Lobby is not an Unreal game server and does not provide the actual game network connection by itself.

Creating or joining a lobby only creates the Steam lobby relationship between players.

Use the Multiplayer feature if you want the plugin to create and manage the actual Steam networking and Unreal listen-server connection.

Does Host Steam Game create a Lobby automatically?

Yes.

Host Steam Game creates the managed Steam lobby and starts the Unreal listen server as part of the same high-level flow.

You do not need to create a lobby manually before calling Host Steam Game.

Can I create my own Lobby first and then start Multiplayer from it?

Yes.

This is useful when you want to build your own pre-game lobby flow using the low-level Lobbies feature.

For example, you can:

  1. Create a Steam Lobby.
  2. Manage lobby data and member data yourself.
  3. Implement ready states, character selection, teams, or other pre-game logic.
  4. When the host is ready, call Start Steam Game From Current Lobby.

The Multiplayer feature then starts the managed networking flow using the current lobby instead of creating a new one.

What is Multiplayer Version?

Multiplayer Version is a project-defined compatibility value used by the managed Multiplayer system.

It allows your project to prevent incompatible game versions from being matched together.

For example, if a networking or gameplay update makes version 1.1 incompatible with 1.0, clients and hosts can use different Multiplayer Version values so they are not treated as compatible games.

Use the same Multiplayer Version for clients and hosts that should be able to play together.

Do I need to configure a listen server manually when using Multiplayer?

No.

The managed Multiplayer feature handles the Unreal listen-server and Steam connection flow for you.

You do not need to manually build a separate listen-server connection system when using Host Steam Game, Find Steam Games, and Join Steam Game.

Do I need to set a Steam connect string manually when using Multiplayer?

No.

The managed Multiplayer feature automatically manages the connect string it requires for its Steam Join Game flow.

Use Set Steam Connect String manually only when your project uses its own connection flow or lower-level Steam features instead of the managed Multiplayer system.

Can players join a game after it has started?

Games created with Host Steam Game use a joinable managed lobby, so players can continue to discover and join the hosted game.

If you build a custom pre-game lobby with the lower-level Lobbies feature and then call Start Steam Game From Current Lobby, use Allow Join In Progress to decide whether that existing lobby remains joinable after the managed game starts.

How do I invite a Steam friend to the current game?

You can either:

  • use Invite Player To Steam Game when you already know the target player's FSteamUserID
  • use Open Steam Invite Dialog For Current Game to let the local player choose a friend through Steam

The current managed game lobby is resolved automatically.

How should I react when a Steam invitation is accepted?

Subscribe to Steam Game Invitation Accepted.

The callback provides the target Lobby ID and the source user when available.

A typical flow is:

  1. Subscribe when your multiplayer UI or persistent game object becomes active.
  2. Store the returned listener handle.
  3. When the event fires, call Join Steam Game with the returned Lobby ID.
  4. Use the same Multiplayer Version expected by the current build.
  5. Unsubscribe when the listener is no longer needed.

Do persistent Multiplayer event subscriptions need to be removed?

Yes.

Subscribe functions return listener handles.

Store the returned handle and pass it to the matching unsubscribe function when the listener is no longer required.

This applies to persistent events such as:

  • player joined
  • player left
  • connection failed
  • game disconnected
  • host disconnected
  • invitation accepted
  • travel events

Voice Chat

Do I need to call Start Steam Voice Chat more than once?

Normally, no.

After hosting or joining a managed multiplayer game, call Start Steam Voice Chat once before using Voice Chat functionality.

You do not need to call it again when:

  • changing Voice Input Mode
  • enabling or disabling Voice Chat
  • muting players
  • changing player volume
  • changing Voice Activation settings
  • switching Voice Chat mode

If Stop Steam Voice Chat is called, you must call Start Steam Voice Chat again before using Voice Chat.

Is Voice Chat enabled automatically after Start Steam Voice Chat?

Yes.

When Start Steam Voice Chat succeeds, Voice Chat is enabled automatically.

You do not need to call:

Set Steam Voice Chat Enabled(true)

immediately after starting it.

What is the difference between Stop Steam Voice Chat and Set Steam Voice Chat Enabled(false)?

Set Steam Voice Chat Enabled(false) temporarily disables local microphone transmission and remote voice playback while keeping the Voice Chat system running.

You can later call:

Set Steam Voice Chat Enabled(true)

to resume Voice Chat.

Stop Steam Voice Chat fully stops the current Voice Chat runtime.

After stopping it, call Start Steam Voice Chat again before using Voice Chat.

Is Set Steam Voice Activation Threshold required?

No.

When Voice Input Mode is set to VoiceActivation, the current activation threshold is used automatically.

Call Set Steam Voice Activation Threshold only when you want to customize the sensitivity.

The threshold is a normalized value between 0 and 1.

How does Push To Talk work?

Set Steam Voice Input Mode to PushToTalk.

This normally only needs to be done once when configuring the input mode.

Then:

  • call Set Steam Push To Talk Active(true) when the Push To Talk input is pressed
  • call Set Steam Push To Talk Active(false) when the input is released

The Push To Talk active state only affects Voice Chat while the input mode is PushToTalk.

Why does Proximity Voice need an Actor?

Proximity Voice needs a world-space source for each remote player's voice.

Use Set Steam Player Voice Actor to associate a remote Steam user with the Actor representing that player in the world.

The plugin can then use the Actor's position as the voice source for distance attenuation and optional spatialization.

Clear the association when the player leaves or the Actor is no longer valid.

How do I configure Proximity Voice distance?

Use Set Steam Proximity Voice Distances.

You can configure:

  • Full Volume Distance
  • Maximum Distance
  • whether spatialization is enabled

Remote voice plays at full volume inside the full-volume distance and fades toward silence by the maximum distance.

Distance values use Unreal units.

Are mute and player volume settings local?

Yes.

Muting a remote player or changing their Voice Chat volume affects how that remote player's voice is played for the local user.

Use:

  • Mute Steam Player
  • Unmute Steam Player
  • Set Steam Player Volume
  • Get Steam Player Volume

to implement local player-specific voice controls.

Steam Input

Do I need to initialize Steam Input manually?

Normally, no.

The plugin attempts to initialize Steam Input automatically.

Use Initialize Steam Input when you want to explicitly initialize or verify that the Steam Input interface is available.

Why does Steam Input use Action names instead of controller buttons?

Steam Input is action-based.

Instead of asking for a specific physical button, the game requests a named action such as:

  • Jump
  • Move
  • Interact

Steam resolves the player's current controller binding for that action.

This allows the same gameplay action to work across different controller layouts and user-customized bindings.

Do Action Set and Action names need to match Steamworks exactly?

Yes.

Names passed to Steam Input functions must match the Action Sets and Actions configured for the application.

For example, if your configuration defines:

  • Action Set: Gameplay
  • Digital Action: Jump

use those exact names when activating the Action Set or reading the Action.

Why does a Digital or Analog Action not return the expected value?

Check the following:

  • Steam Input initialized successfully
  • a valid FSteamInputDevice is being used
  • the device is still connected
  • the correct Action Set is active
  • the Action name matches the Steam Input configuration
  • the Action belongs to the currently active Action Set or layer
  • the controller is being handled through Steam Input

You can use Is Steam Digital Action Active to check whether a digital action is currently available.

How do I get the correct controller button icon?

Do not hard-code a specific Xbox, PlayStation, or other controller icon.

Instead:

  1. Get the Action Origin for the relevant Digital or Analog Action.
  2. Pass the returned FSteamInputOrigin to Get Steam Input Glyph.
  3. Display the returned texture in your UI.

This allows Steam to provide the glyph that matches the player's current controller and binding.

Do I need to activate an Action Set before reading actions?

Yes, when that action belongs to an Action Set that is not currently active.

Use Activate Steam Input Action Set with the target device and Action Set name.

Steam Input reads actions according to the currently active Action Set and any active Action Set Layers.

What are Action Set Layers used for?

Action Set Layers temporarily add or modify actions on top of the currently active Action Set.

They are useful for temporary contexts such as:

  • radial menus
  • vehicles
  • interaction modes
  • temporary overlays
  • context-specific controls

Use Activate Steam Input Action Set Layer to enable a layer and the corresponding deactivate functions to remove it.

Achievements, Stats, and Leaderboards

Does Indicate Steam Achievement Progress save achievement progress?

No.

Indicate Steam Achievement Progress shows Steam's achievement progress notification.

It does not persist progress by itself and does not unlock the achievement.

If your achievement uses incremental progress, store the actual progress separately, for example through Steam Stats or your own game data, and unlock the achievement when the required condition is reached.

Do I need to store Steam Stats after changing them?

Changes made to Steam Stats should be stored when you want the updated values submitted to Steam.

Use Store Steam Stats after the relevant stat changes according to your game's save/update flow.

Avoid unnecessarily storing stats every frame.

Why can I not find my Steam Leaderboard?

Check:

  • the leaderboard name
  • the current Steam App ID
  • the leaderboard configuration in Steamworks
  • whether the leaderboard exists for the current application
  • whether you are searching under the correct application

When using App ID 480, leaderboard data belongs to Spacewar rather than your own Steamworks application.

Can I create a Leaderboard from the game?

Use the plugin's find-or-create workflow when your project intentionally allows the leaderboard to be created at runtime.

For production projects, make sure your leaderboard naming and Steamworks configuration are consistent with the design of your application.

Cloud Saves

Does Steam Cloud automatically save my Unreal SaveGame object?

No.

Steam Cloud synchronizes files, but your game still decides when data should be written.

Use:

  • Save Game To Steam Cloud for an Unreal USaveGame workflow
  • Write Steam Cloud Save for raw byte data

Steam then handles synchronization of the resulting cloud files.

What is the difference between Save Game To Steam Cloud and Write Steam Cloud Save?

Save Game To Steam Cloud is a higher-level Unreal workflow.

It serializes a USaveGame object and writes it to Steam Cloud.

Write Steam Cloud Save is a lower-level file API.

It writes an array of bytes directly and is useful for custom formats or data that does not use Unreal's SaveGame system.

Can I use multiple Cloud save slots?

Yes.

Use different file names for different save slots.

For example:

SaveSlot_1
SaveSlot_2
AutoSave

Use the same file name when loading, checking, or deleting the corresponding cloud file.

Why does a Cloud save not exist on another device immediately?

Steam Cloud synchronization is managed by Steam.

Your game writes and reads cloud files through the Steam Cloud API, while synchronization between machines is handled by the Steam client.

For final cross-device testing, close the game normally and allow Steam to complete synchronization before launching the game on another device.

DLC

Which App ID should I use with DLC functions?

Use the DLC App ID, not the base game's App ID.

Each DLC application has its own Steam App ID.

Pass that DLC App ID to DLC-specific functions such as installation checks, installation requests, and download progress queries.

What DLC state does the plugin expose?

Use Is Steam DLC Installed when you need to know whether a DLC is currently installed on the local machine.

Get Steam DLC List also returns FSteamDLCInfo, including the availability and installed state reported by Steam for each DLC entry.

The DLC feature does not expose a separate ownership or entitlement query beyond these reported DLC values.

Why does Install Steam DLC not start a download?

Check the DLC configuration in Steamworks.

On-demand installation requires the DLC and its depot configuration to support that workflow.

Also verify:

  • the correct DLC App ID is being used
  • the current Steam account has access to the DLC
  • the DLC is associated with the correct base application
  • the DLC is configured so Steam does not automatically install it when that is required for your on-demand flow

See DLC Steamworks Setup.

How do I know when a DLC installation has finished?

Subscribe to Steam DLC Installed before requesting the installation.

When Steam reports that installation has completed, the callback provides the DLC App ID.

Store the returned listener handle and unsubscribe when the listener is no longer needed.

You can also use Get Steam DLC Download Progress while a download is active.

Rich Presence

Why is my Rich Presence text not visible?

For localized Rich Presence, verify that:

  • the Rich Presence localization file is configured
  • it has been published in Steamworks
  • the expected localization token exists
  • the required custom values referenced by the token are set
  • the steam_display value points to the expected token

Setting arbitrary presence values does not automatically create visible localized text unless the active Steam display template uses them.

Do I need to set steam_display every time another Rich Presence value changes?

Not necessarily.

You can update custom Rich Presence values independently.

If the same steam_display template remains active, Steam can continue using that template with the updated values.

Change steam_display when you want to switch to a different display layout or localization token.

Do I need to set the Steam connect string manually when using managed Multiplayer?

No.

Managed Multiplayer handles the connect string required for its Join Game flow automatically.

Use Set Steam Connect String manually only when implementing your own connection flow.

Friends, User, and Overlay

Why can I not see a Steam friend's current game information?

Steam can only return information that is available for that friend and permitted by Steam.

The friend may be:

  • offline
  • not currently playing a game
  • playing a game whose information is not available to the current user

Always handle missing friend game information as a normal state.

Why does the Steam Overlay behave differently between Editor and packaged builds?

The Editor environment is not identical to a normal Steam-launched process.

Overlay behavior can depend on:

  • the active game window
  • focus
  • launch context
  • Steam process integration

For reliable Overlay testing, use a packaged build launched through Steam.

Can I open a Steam user's profile from the game?

Yes.

Use the Overlay feature to open the appropriate Steam user/profile dialog when the Steam Overlay is available.

The exact user must be identified with a valid Steam user ID.

Screenshots

Does taking an Unreal screenshot automatically send it to Steam?

No.

Steam screenshot functionality and Unreal's own screenshot functionality are separate.

Use the plugin's Steam Screenshots functions when you want the screenshot to be submitted or handled through Steam's screenshot system.

Can I provide my own screenshot image to Steam?

Yes.

Use the custom screenshot workflow exposed by the Screenshots feature when your project needs to submit image data that was generated or captured by the game.

Steam Publishing Tool

What does the Steam Publishing Tool do?

The Steam Publishing Tool provides an editor workflow for preparing and uploading builds through SteamPipe.

Depending on the selected Publishing Build Mode, it can work with a newly packaged project or an existing packaged build folder.

The tool uses the publishing settings configured under:

Edit → Project Settings → Plugins → PloxTools: Steam Integration

Does the Steam Publishing Tool use the same Steam App ID as the runtime plugin?

Yes.

The Steam App ID configured in the plugin settings is used by both:

  • the runtime Steam integration
  • the Steam Publishing Tool

Make sure the App ID belongs to the Steamworks application you intend to publish.

Can I upload an already packaged build?

Yes.

Select the Publishing Build Mode intended for an existing build and provide the Publishing Existing Build Folder.

This allows the Steam Publishing Tool to upload a packaged build without packaging the Unreal project again.

What is Publishing Package Directory?

This is the output directory used when the Publishing Tool packages the Unreal project before upload.

It applies to publishing modes that include project packaging.

What is Publishing Existing Build Folder?

This is the folder containing a build that has already been packaged.

It is used by publishing modes that upload an existing build rather than packaging the project first.

What does Preview Upload Only do?

Preview Upload Only is intended for checking the generated publishing workflow without performing the normal final upload operation.

Use it when validating publishing configuration before a real Steam upload.

For generated files and logs, see Logs and Generated Files.

Can I keep the generated SteamPipe files?

Yes.

Enable Keep Generated SteamPipe Files if you want the generated SteamPipe configuration files to remain available after the publishing operation.

This can be useful for troubleshooting or reviewing the generated upload configuration.

Can I save the upload log?

Yes.

Enable Save Upload Log to keep the publishing log generated by the tool.

Saved logs are useful when troubleshooting failed uploads or reviewing SteamPipe output.

Where should I configure the Depot ID?

Set Publishing Depot ID in the plugin's publishing settings.

The Depot ID must correspond to the Steamworks depot that should receive the uploaded build content.

See the Steam Publishing Tool Setup section for the complete publishing configuration.

General Troubleshooting

A Steam function suddenly stopped working after changing the App ID

Restart Unreal Engine.

The Steam App ID is read when the Steam module starts.

Also verify that the new application has the corresponding Steamworks feature configured. Features such as achievements, leaderboards, Cloud, DLC, Rich Presence, and Steam Input are application-specific.

A function works with App ID 480 but not with my own App ID

This normally indicates that the runtime Steam integration itself is working, but the corresponding feature may not yet be configured for your own Steamworks application.

Check the Steamworks Setup page for that feature.

Examples include:

  • Achievements
  • Cloud Saves
  • DLC
  • Leaderboards
  • Rich Presence
  • Stats
  • Steam Input

Should I test every Steam feature only in packaged builds?

No.

PIE and Standalone Game are useful during development.

However, final validation should be performed in a packaged build launched through Steam, especially for features that depend heavily on Steam launch context, networking, world travel, Overlay, or multiple Steam users.

Where should I look first when a Steam feature fails?

Start with:

  1. Is Steam Initialized
  2. the current Steam App ID
  3. the relevant Steamworks configuration
  4. the failure callback or returned error message
  5. whether the feature behaves differently in a packaged build through Steam

Then check the corresponding Examples, Steamworks Setup, and API Reference pages for that feature.
