Testing Steam Functionality

Testing Steam integration requires the Steam client to be running and properly authenticated. Steam functionality is not available in isolation and always depends on the Steam runtime environment.

Regardless of the testing method used, the following conditions must be met:

  • The Steam client must be running
  • You must be logged into a Steam account
  • The Steam account must have access to the application when testing your own Steam App ID
  • The correct Steam App ID must be configured

If you are testing from the Unreal Editor, Enable Steam In Editor must also be enabled in:

Edit → Project Settings → Plugins → PloxTools: Steam Integration → Development

If these conditions are not met, Steam API calls may fail or return no data.

For initial setup, see Getting Started.

Testing in the Unreal Editor

For fast iteration during development, the plugin can initialize Steam directly while the project is running from the Unreal Editor.

This allows most Steam functionality to be tested without packaging and uploading a new build after every change.

Before testing, make sure that:

  • The Steam client is running
  • You are logged into Steam
  • The correct Steam App ID is configured
  • Your Steam account has access to the application when using your own App ID
  • Enable Steam In Editor is enabled

Note

The Steam App ID and Enable Steam In Editor settings are read when the Steam module starts.

Restart Unreal Engine after changing either setting before testing Steam integration.

PIE

Steam can be initialized while running the game in Play In Editor (PIE).

PIE is useful for:

  • Fast API validation
  • Checking Blueprint and C++ logic
  • Testing callbacks
  • Testing player data such as stats and achievements
  • Verifying that Steam initializes correctly

Some Steam features may behave differently in PIE because the game is still running inside the Unreal Editor process.

For features that depend on window behavior, Overlay interaction, networking, or a more production-like runtime environment, Standalone Game or an uploaded Steam build is recommended.

Standalone Game

Standalone Game also runs from the Unreal Editor while providing a more independent game window.

It is generally preferable when testing:

  • Overlay behavior
  • Window focus and Steam UI interaction
  • Networking-related functionality
  • Features that should be validated outside the PIE viewport

Standalone testing is still an editor-based development workflow and should not be treated as a complete replacement for testing an uploaded Steam build.

Testing with the Spacewar App ID

If your application has not yet been created in Steamworks, limited testing can be performed using the official Steam test App ID 480.

Using the Spacewar App ID allows you to:

  • Verify that Steam initializes correctly
  • Test basic Steam API calls
  • Check whether local Steam runtime integration is working

However, Spacewar does not represent your real application.

Important limitations:

  • Application-specific achievements, stats, leaderboards, and cloud saves will not match your own game
  • Data belongs to the Spacewar test application, not your application
  • Application access, package, and DLC configuration are not representative of your real product
  • Production behavior must still be verified with your own Steam App ID

Use App ID 480 only for early validation or troubleshooting.

Editor Testing Limitations

Testing from PIE or Standalone is useful for development, but it is still a local editor workflow.

Some Steam features may behave differently compared to a real Steam launch, especially features that depend on:

  • Application access and package configuration
  • Branch configuration
  • Depots
  • Steam Cloud configuration
  • DLC package and installation configuration
  • Steam Input configuration
  • Overlay behavior
  • Release state
  • Real multiplayer connections between separate Steam users

For best results, use PIE or Standalone during development and validate important features again through uploaded Steam builds before release.

Editor testing is suitable for:

  • Fast API validation
  • Checking Blueprint and C++ logic
  • Testing callbacks
  • Testing basic Steam initialization
  • Testing your configured Steam App ID before uploading a build

It should not be treated as a full replacement for production testing through Steam.

Testing Through Steam Builds

For accurate and production-like testing, the game should be uploaded and launched through Steam.

The plugin includes a built-in Steam Publishing Tool that allows you to configure, validate, and upload prepared game builds through SteamCMD directly from the Unreal Editor.

The recommended workflow is:

  1. Package your game build
  2. Open the Steam Publishing Tool
  3. Configure the Steam App ID, Depot ID, build folder, executable, and target branch
  4. Authorize your Steam account
  5. Review the pre-flight summary
  6. Publish the build to Steam
  7. Launch the uploaded build directly from the Steam client

Testing through Steam provides the most reliable results and ensures that Steam features behave as they will for end users.

This method is strongly recommended when validating:

  • Achievements
  • Leaderboards
  • Cloud Saves
  • Rich Presence
  • Overlay behavior
  • Application access and package configuration
  • DLC
  • Steam Input
  • Multiplayer
  • Voice Chat
  • Final release behavior

The Publishing Tool simplifies the SteamPipe upload workflow, but your application, depots, branches, permissions, and related Steamworks settings must still be configured correctly in the Steamworks Partner Portal.

For additional information about SteamPipe configuration and build management, refer to the official Steamworks documentation.

Multiplayer Testing

Multiplayer should be tested with the same Steam conditions that will exist for real players.

For meaningful multiplayer testing, use:

  • Separate game instances
  • Separate Steam accounts when required by the tested workflow
  • Steam accounts that have access to the application
  • The same Steam App ID on all participating clients

For early development, basic multiplayer logic can be tested from the Unreal Editor where practical.

However, final validation should be performed using packaged builds launched through Steam, especially when testing:

  • Hosting and joining multiplayer sessions
  • Steam lobby creation and discovery
  • Invites
  • Player connections
  • Client and server travel
  • Voice Chat
  • Proximity Voice Chat
  • Reconnection and disconnect behavior

Testing through Steam provides the closest environment to the one your players will use.

Recommended Testing Workflow

A typical development workflow is:

  1. Use PIE or Standalone Game for fast iteration during development
  2. Use your own Steam App ID whenever possible
  3. Use App ID 480 only for early validation or troubleshooting
  4. Use uploaded Steam builds for production-like feature testing
  5. Test multiplayer and platform-dependent features with real Steam accounts
  6. Perform final validation by launching the game directly through Steam

This approach keeps iteration fast while still ensuring that important Steam functionality is validated in a production-like environment.

Common Issues During Testing

If Steam functionality does not work as expected, verify the following:

  • The Steam client is running and logged in
  • The correct Steam App ID is configured in the plugin settings
  • The Steam account has access to the application
  • Enable Steam In Editor is enabled when testing in PIE or Standalone
  • Unreal Engine was restarted after changing the Steam App ID or Enable Steam In Editor setting
  • No conflicting Steam integration plugins are active in the project
  • The application is properly configured in Steamworks when testing application-specific features
  • All multiplayer clients are using the same Steam App ID
  • Separate Steam accounts are used when required by the multiplayer test

Most Steam-related issues during development are caused by missing Steam client state, incorrect App ID configuration, missing application access, or testing a feature in an environment that does not fully match a real Steam launch.

For detailed instructions on uploading builds and managing branches, see the Steam Publishing Tool.
