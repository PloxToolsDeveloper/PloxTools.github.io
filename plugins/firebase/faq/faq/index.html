FAQ

This page covers common questions and issues related to Firebase configuration, initialization, authentication, Cloud Messaging, databases, storage, and production setup.

For step-by-step setup instructions, see Getting Started.

Installation and Configuration

Firebase initialization fails

First, verify that the correct Firebase configuration file is assigned in the plugin settings.

  • Android: google-services.json
  • iOS: GoogleService-Info.plist

Make sure the configuration file belongs to the Firebase app registered for the platform you are currently building.

Also verify that the Android Package Name or iOS Bundle ID matches the application registered in Firebase.

See Getting Started and Initialization for the complete setup.

What is the difference between google-services.json and GoogleService-Info.plist?

They are platform-specific Firebase configuration files.

  • google-services.json is used by Android.
  • GoogleService-Info.plist is used by iOS.

If your project supports both platforms, register both an Android app and an iOS app inside your Firebase project and configure both files.

Can the same Firebase project be used for Android and iOS?

Yes.

A single Firebase project can contain separate Android and iOS applications.

Each platform must still be registered separately and use its own configuration file and application identifier.

Do I need to install the Firebase SDK manually?

No.

The plugin includes and integrates the required Firebase dependencies for the supported Android and iOS services.

Do not manually add another Firebase integration unless you specifically need functionality outside the plugin, as duplicate dependencies may cause build conflicts.

The IDE does not recognize the plugin C++ headers

Add PloxToolsFirebase to your project's *.Build.cs dependencies.

After changing the module dependencies:

  1. Regenerate the project files.
  2. Reopen the IDE.
  3. Rebuild the project.

If the headers are still unresolved, remove the project's Binaries and Intermediate folders and regenerate the project files again.

Authentication

Which authentication methods are supported?

The plugin supports:

  • Email & Password on Android and iOS
  • Google Sign-In on Android
  • Sign in with Apple on iOS

Other Firebase Authentication providers are not currently exposed by the plugin.

Can Email & Password authentication be used on both Android and iOS?

Yes.

The same Email & Password authentication API can be used on both supported platforms.

Make sure the Email/Password provider is enabled in Firebase Console → Authentication → Sign-in method.

Is Google Sign-In supported on iOS?

No.

Google Sign-In is currently provided by the plugin on Android.

For native social authentication on iOS, use Sign in with Apple.

Is Sign in with Apple supported on Android?

No.

Sign in with Apple is currently implemented for iOS.

Android users can use Email & Password or Google Sign-In.

Why does Sign in with Apple fail on iOS?

Sign in with Apple requires additional Apple-side configuration outside the plugin.

Verify that:

  • the application uses a paid Apple Developer Program account;
  • Sign in with Apple is enabled for the App ID;
  • the required entitlement is included in the signed application;
  • the Apple provider is enabled and configured in Firebase Authentication;
  • the Bundle ID matches the Firebase iOS application.

See the Authentication documentation for the complete setup.

Cloud Messaging

Do I need to request notification permission?

Yes, when required by the operating system.

Use Request Cloud Messaging Notification Permission.

  • iOS: the function requests notification authorization from the user.
  • Android 13+ (API 33+): the function requests POST_NOTIFICATIONS.
  • Android 12 and lower: no runtime notification permission is required.

Why are notifications not appearing on Android 13 or higher?

Android 13+ requires the POST_NOTIFICATIONS runtime permission.

Call Request Cloud Messaging Notification Permission and make sure the user grants permission before expecting notifications to appear.

The plugin already declares the required permission in the Android manifest.

Why are notifications not arriving on iOS?

iOS push notifications require additional Apple Push Notification service configuration.

Verify that:

  • Push Notifications are enabled for the App ID;
  • the application is signed with a provisioning profile that includes the push notification entitlement;
  • an APNs authentication key or certificate is configured in Firebase;
  • notification permission has been granted by the user;
  • the application is running on a real iOS device.

The plugin handles Firebase Messaging integration, but Apple signing and APNs credentials must be configured for the project.

Do I need to configure APNs for iOS?

Yes.

Firebase Cloud Messaging uses Apple Push Notification service to deliver remote notifications to iOS devices.

Configure an APNs authentication key or certificate in the Firebase Console under the iOS application's Cloud Messaging settings.

Why is the FCM token empty?

The token may not be immediately available when the application starts.

Make sure Firebase and Cloud Messaging are initialized and wait for token generation before relying on it.

On iOS, APNs registration and the required Apple configuration must also complete successfully.

Can a device subscribe to multiple topics?

Yes.

A device can subscribe to multiple Firebase Cloud Messaging topics.

Use the topic subscription functions separately for each topic you want the device to receive.

Firebase Services

Do all Firebase services require Authentication?

No.

Authentication is only required when your Firebase configuration, Security Rules, or application logic requires an authenticated user.

Services such as Analytics, Crashlytics, Remote Config, and Performance Monitoring can be used without signing the user in.

Firestore, Realtime Database, and Cloud Storage access depends on the Security Rules configured in your Firebase project.

Firestore, Realtime Database, or Cloud Storage returns Permission Denied

This usually means the Firebase Security Rules do not allow the requested operation.

Security Rules are configured in the Firebase Console and are not modified automatically by the plugin.

Check:

  • whether the user must be authenticated;
  • whether the requested path is allowed;
  • whether read and write permissions are configured correctly;
  • whether the rules have been published.

Does the plugin configure Firebase Security Rules?

No.

Firestore, Realtime Database, and Cloud Storage Security Rules belong to your Firebase backend configuration.

The plugin only sends requests using the credentials and authentication state of the current application.

Can Analytics, Crashlytics, Remote Config, and Performance Monitoring be used independently?

Yes.

You only need to use the Firebase services required by your project.

After Firebase has been initialized, individual services can be used independently unless a specific workflow depends on another Firebase service.

Build and Production

Does the plugin use the same Blueprint API on Android and iOS?

Yes, wherever the underlying Firebase functionality is equivalent.

Most Blueprint and C++ functions are shared between Android and iOS.

Platform-specific features such as Google Sign-In and Sign in with Apple are exposed separately where required.

Do I need separate Firebase applications for Android and iOS?

Yes.

Android and iOS should be registered as separate applications inside the same Firebase project.

The Android app uses its Package Name and google-services.json, while the iOS app uses its Bundle ID and GoogleService-Info.plist.

Can I use the Firebase Console while the application is still in development?

Yes.

Firebase projects and services can be configured and tested during development.

You can inspect Authentication users, Analytics events, Firestore data, Realtime Database data, Storage files, Crashlytics reports, Remote Config values, and other Firebase data from the Firebase Console.

What should I check before publishing the application?

Before release:

  1. Verify that the correct Android Package Name and iOS Bundle ID are registered in Firebase.
  2. Verify that the correct Firebase configuration file is assigned for each platform.
  3. Confirm that Firebase Security Rules are appropriate for production.
  4. Confirm that required Authentication providers are enabled.
  5. For iOS Cloud Messaging, verify APNs configuration and push notification capabilities.
  6. For Sign in with Apple, verify Apple Developer and Firebase provider configuration.
  7. Test the packaged application on a real device before publishing.
