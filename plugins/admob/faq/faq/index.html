FAQ

This page covers common questions and issues related to installation, configuration, ad loading, consent, mediation, and supported ad formats.

For step-by-step setup instructions, see Getting Started. For exact function signatures and enum values, see the Technical Reference.

Installation and Build

The packaged application crashes when calling any plugin function

In very rare cases, an Android or iOS package may be generated incorrectly by Unreal Engine. When this happens, the application can crash as soon as any native plugin function is called, even when the plugin integration itself is correct.

This issue has been observed most often with Unreal Engine 5.6. On Android, one sign of an incorrect package can be an unexpected output filename without the usual platform and configuration suffix. For example:

MyProject.aab

instead of:

MyProject-Android-Shipping.aab

This does not prove that the package is broken, but it can indicate that the mobile packaging process did not complete normally.

If the application crashes immediately when calling otherwise valid plugin functions:

  1. Test the same project with a clean package.
  2. Delete the project's Binaries, Intermediate, and Saved folders.
  3. Reinstall or verify the current Unreal Engine installation.
  4. As the most reliable solution, move the project to a newer supported Unreal Engine version and package it again.

The same type of packaging corruption may also affect iOS builds. Because this is an engine-level packaging issue and can be difficult to diagnose, testing the project in a newer engine version is usually the fastest way to confirm whether the plugin is involved.

The Android Minimum SDK unexpectedly becomes 35

In rare cases, Unreal Engine may generate an Android package with an incorrect minSdkVersion, even when a lower Minimum SDK is selected in Project Settings.

This can significantly reduce device compatibility because Android 35 would then be treated as the minimum supported version instead of the target version.

If the value cannot be corrected from Unreal Engine's Android settings, locate the following file inside the Unreal Engine installation and open it with any text editor:

Engine/Build/Android/Java/gradle/app/build.gradle

At the beginning of the file, find the SDK version entries and set them manually. For example:

minSdkVersion = 26
targetSdkVersion = 35

The result should look similar to this:

android {
    namespace PACKAGE_NAME
    ndkVersion NDK_VERSION
    ndkPath NDK_PATH
    compileSdk COMPILE_SDK_VERSION.toInteger()
    buildToolsVersion BUILD_TOOLS_VERSION

    defaultConfig {
        applicationId PACKAGE_NAME
        minSdkVersion = 26
        targetSdkVersion = 35
        versionCode STORE_VERSION.toInteger()
        versionName VERSION_DISPLAY_NAME
    }

    buildFeatures {
        aidl true
        buildConfig true
    }
}

Warning

This file belongs to the Unreal Engine installation and affects Android builds created with that engine version.

Back up the original file before editing it. Verifying, repairing, or updating the engine may overwrite the change.

The Android build fails after enabling the plugin

Make sure Unreal Engine's built-in AdMob integration and any other third-party AdMob plugins are disabled.

For Android, also verify that Include AdMob support for ads is disabled under:

Project Settings → Android → Google Play Services

Conflicting integrations may add duplicate SDK dependencies, manifest entries, or platform code.

If the problem continues, verify that the Android NDK version is compatible with your Unreal Engine version. You can also remove the project's Binaries, Intermediate, and Android build cache folders before packaging again.

The iOS build fails after enabling App Tracking Transparency

Verify that Tracking Usage Description contains a valid message and rebuild the application after changing the setting.

Also confirm that the iOS project is correctly signed and that the required Apple development team is configured.

ATT settings affect the packaged iOS application, so changes require a new build.

The IDE does not recognize AdMobCPPLibrary.h

Add "PloxToolsAdMob" to your project's *.Build.cs dependencies.

After updating the module list:

  1. Regenerate the project files.
  2. Reopen the IDE.
  3. Rebuild the project.

If the include is still unresolved, remove the project's Binaries and Intermediate folders and regenerate the project files again.

See C++ Usage for the complete setup.

Initialization and Configuration

AdMob initialization does not complete

Check the following:

  • the App ID is configured in the plugin settings;
  • the value is an App ID, not an Ad Unit ID;
  • the App ID belongs to the current target platform;
  • no other AdMob integration is active in the project;
  • the application has network access.

Android and iOS use separate App IDs. An Android App ID should not be used in an iOS build, and an iOS App ID should not be used in an Android build.

Can I use one AdMob application for both Android and iOS?

No.

Android and iOS must be registered as separate applications in AdMob. Each platform has its own:

  • App ID;
  • Ad Unit IDs;
  • privacy message configuration;
  • mediation configuration.

Use the identifiers created for the platform currently being packaged.

Can the plugin be used without Google UMP?

Yes.

AdMob can technically be initialized and ads can be requested without running the UMP consent flow.

UMP is used to collect and apply privacy choices that may be required for the current user, region, audience, or advertising configuration. Applications that use UMP should complete the consent flow before proceeding with advertising requests.

See Consent & Privacy for details.

Ad Loading and Display

An ad does not load

Check the failure callback and application logs first.

Common causes include:

  • an incorrect or empty Ad Unit ID;
  • using an Android ID in an iOS build or an iOS ID in an Android build;
  • AdMob initialization not completing;
  • no network connection;
  • no available inventory;
  • an incorrect App ID;
  • an ad already loading or already loaded.

During development, use Google's official demo Ad Unit IDs from Testing.

The Show function fails

A fullscreen ad must be loaded successfully before it can be shown.

Wait for the corresponding On Loaded callback or check the relevant readiness function:

  • Is Interstitial Ready
  • Is Rewarded Ready
  • Is Rewarded Interstitial Ready
  • Is App Open Ready

Fullscreen ads can be shown only once. After an ad has been displayed, load another ad before calling the Show function again.

Can a fullscreen ad be shown more than once?

No.

Interstitial, Rewarded, Rewarded Interstitial, and App Open ads are single-use objects. After an ad is shown, another ad must be loaded before the next display.

You can load the next ad manually or enable Auto Reload.

Why does Auto Reload not show another ad automatically?

Auto Reload only requests and prepares the next ad after the current ad closes.

It does not display another ad automatically. The application must still call the corresponding Show function when the next ad should appear.

What does Immersive Mode do?

Immersive Mode requests fullscreen presentation with supported system interface elements hidden while the ad is displayed.

Its exact behavior depends on the platform, operating system, device configuration, and ad content.

Banner

What is the difference between Hide Banner and Destroy Banner?

Hide Banner removes the banner from view but keeps the current banner instance loaded. It can be shown again without another load request.

Destroy Banner removes the banner instance completely. A new banner must be loaded before it can be displayed again.

Why does the banner not fit the screen correctly?

The selected fixed banner size may be too large for the current device, orientation, or available layout space.

For responsive phone layouts, consider using Anchored Adaptive.

Also verify the selected gravity, offsets, screen orientation, and whether the banner overlaps the application's safe area or interface elements.

Can the banner position be changed without reloading it?

Yes.

Call Show Banner again with a different gravity or offset. The current banner does not need to be reloaded.

Rewarded Ads

Which callback should grant the reward?

Grant the reward only from On Reward Earned.

This callback confirms that the native advertising SDK reported the reward and provides the configured reward amount and type.

Do not grant the reward from On Started, On Completed, or fullscreen events.

Why did On Completed trigger without a reward?

On Completed only confirms that the fullscreen ad was closed or finished displaying.

It does not confirm that the user earned the reward. Reward delivery is reported separately through On Reward Earned.

What is the difference between Rewarded and Rewarded Interstitial?

A standard Rewarded ad is normally started through a deliberate user action, such as pressing a Watch Ad for Reward button.

A Rewarded Interstitial can be offered at a natural transition point, but the user must first be informed about the reward and given a clear way to continue without viewing the ad.

Both formats must grant the reward only through On Reward Earned.

App Open

What is the difference between manual and automatic App Open mode?

Manual mode gives the application direct control over loading and showing the ad.

Automatic mode allows the plugin to monitor foreground transitions, load App Open ads, and attempt to show them when the application returns to the foreground and the configured minimum interval has passed.

Use manual mode when exact timing is required. Use automatic mode for consistent resume handling.

Why was an App Open ad not shown after returning to the application?

Possible reasons include:

  • automatic mode is disabled;
  • the minimum interval has not passed;
  • no App Open ad was ready;
  • the previous ad is still active;
  • the ad failed to load;
  • the application returned to the foreground before the next ad finished loading.

If no ad is ready, the plugin does not delay the user. It loads an ad for a later foreground transition.

Should manual and automatic App Open modes be used together?

Avoid allowing both modes to control the same placement at the same time.

Automatic mode may attempt to show an ad during the same foreground transition in which the application manually calls Show App Open.

Use one clear ownership model, or disable automatic mode before switching to manual handling.

Consent and Privacy

Why did the consent form not appear?

The absence of a form does not automatically indicate an error.

A form may not appear when:

  • consent is not required for the current user;
  • the user has already completed the current message;
  • no applicable message is configured or published;
  • the message is assigned to a different AdMob application;
  • the user is marked as under the age of consent;
  • the current privacy configuration does not require a form.

Check the completion callback, Can Request Ads, Get Consent Status, and Get Privacy Options Requirement Status.

Does Can Request Ads mean the user accepted personalized advertising?

No.

Can Request Ads indicates that the current UMP privacy state allows the application to proceed with advertising requests.

It does not mean that the user accepted personalized advertising. Ads may also be available when consent is not required or when non-personalized advertising settings apply.

Why does Privacy Options return Not Required?

UMP determines whether the application must provide a user-accessible privacy options entry point for the current user.

Not Required means that the entry point is not currently required. It does not mean that the initial consent request failed.

Check this status only after Request Consent has completed.

Why does the ATT dialog not appear on iOS?

Possible reasons include:

  • Enable App Tracking Transparency is disabled;
  • no IDFA explainer is configured or published for the iOS application in AdMob;
  • the user has already made a tracking choice;
  • the current iOS system state does not allow another request;
  • the ATT request is not applicable to the current privacy flow.

ATT is optional and applies only to iOS. The normal UMP consent flow can still work when ATT is disabled.

Should Under Age Of Consent or Age Restricted Treatment be enabled for every user?

No.

The plugin does not determine the user's age automatically. The application is responsible for obtaining or determining the user's age and deciding whether either setting applies.

Do not enable these settings for all users as a precaution. Incorrect age-related settings may change the consent flow and advertising behavior.

Mediation

Does enabling a mediation network in the plugin complete the setup?

No.

Enabling a mediation option only adds the required Android SDK and AdMob mediation adapter to the packaged application.

You must still:

  • create an account with the selected network;
  • register the Android application;
  • create the required placements or ad units;
  • configure the network in an AdMob mediation group;
  • provide the required credentials and mapping information.

See Mediation for the complete setup.

Is mediation supported on iOS?

The optional third-party mediation adapters provided by the plugin are currently supported only on Android.

iOS builds continue to use the standard AdMob integration without these plugin-provided adapters.

Why is a mediated network not returning ads?

Verify the configuration in both AdMob and the third-party network dashboard.

Check:

  • the Android application registration;
  • placement or ad unit mapping;
  • credentials;
  • bidding or waterfall configuration;
  • mediation group targeting;
  • supported ad formats;
  • adapter initialization;
  • the network's required test mode.

A successful standard AdMob test does not confirm that every mediated network is configured correctly.

Testing and Production

Can I use my production Ad Unit IDs during development?

Do not repeatedly load or interact with production ads during development.

Test impressions and clicks generated with production Ad Unit IDs may be treated as invalid traffic. This can affect ad serving and may lead to restrictions on the AdMob account.

Use Google's official demo Ad Unit IDs until preparing the final release build.

Can Google's sample App IDs be used instead of creating an AdMob application?

They can be used temporarily for a quick integration test.

Normally, use the App IDs from your own Android and iOS applications registered in AdMob. If the application creation step has not been completed yet, Google's official sample App IDs can be configured temporarily.

Replace them with your own platform-specific App IDs before publishing.

What should be replaced before publishing?

Before releasing the application:

  1. Replace any sample App ID with the App ID from your own AdMob application.
  2. Replace every demo Ad Unit ID with the corresponding production Ad Unit ID.
  3. Verify that every identifier belongs to the correct platform and ad format.
  4. Confirm that the required privacy messages are configured and published.
  5. Confirm that no test-only consent reset logic remains in the application.
