FAQ

This page covers common questions and issues related to Google Play Billing initialization, product configuration, purchase processing, pending purchases, ownership, testing, and release builds.

For step-by-step setup instructions, see Getting Started. For exact function signatures and enum values, see the Technical Reference.

Installation and Build

The Android build fails after enabling the plugin

Make sure no other Google Play Billing plugin or custom Billing Library integration is enabled in the same project.

Conflicting integrations may add duplicate Gradle dependencies, Java classes, manifest entries, or native code.

If the problem continues:

  1. Close Unreal Engine.
  2. Delete the project's Binaries, Intermediate, and Saved folders.
  3. Regenerate the project files.
  4. Package the application again.

Also verify that the Android SDK, NDK, and Java versions are compatible with the Unreal Engine version being used.

The packaged application crashes when calling a plugin function

First confirm that the application was packaged with the plugin enabled and that the plugin files were included correctly.

If the crash occurs immediately when any plugin function is called:

  1. Delete the project's Binaries, Intermediate, and Saved folders.
  2. Create a clean package.
  3. Verify or reinstall the current Unreal Engine installation.
  4. Test the project with a newer supported Unreal Engine version.

A corrupted or incomplete Android package can cause native plugin calls to fail even when the plugin code is correct.

The IDE does not recognize GooglePlayBillingCPPLibrary.h

Add "PloxToolsGooglePlayBilling" to the dependency modules in the project's *.Build.cs file.

After updating the module list:

  1. Regenerate the project files.
  2. Reopen the IDE.
  3. Rebuild the project.

If the include is still unresolved, delete the project's Binaries and Intermediate folders and regenerate the project files again.

See C++ Usage for the complete setup.

Initialization

Google Play Billing initialization does not complete

Check the initialization failure callback and application logs.

Common causes include:

  • Google Play services are unavailable or outdated.
  • The device does not have a working Google Play Store installation.
  • The application is not configured correctly in Google Play Console.
  • The package name does not match the application registered in Google Play Console.
  • The device has no network connection.

Do not launch purchases or query products until initialization has completed successfully.

Can Google Play Billing be used outside Google Play?

Google Play Billing is intended for Android applications distributed through Google Play.

The application, package name, products, and testing accounts must be configured through Google Play Console.

Products and Configuration

What is the difference between an In-App Product and a Subscription?

An In-App Product is a one-time product.

It can be either:

  • Consumable, such as virtual currency or energy.
  • Non-consumable, such as removing advertisements or unlocking permanent content.

A Subscription provides access that can renew or remain active according to its base plan and offer configuration in Google Play Console.

What is the difference between consumable and non-consumable products?

A consumable product can be purchased repeatedly.

After a successful automatic purchase, the plugin consumes it so that Google Play allows the same product to be purchased again.

A non-consumable product is purchased once and remains owned by the user's Google Play account.

Add every non-consumable one-time Product ID to Set Google Play Non Consumable Products.

Do I need to call Set Google Play Non Consumable Products?

Only when the application uses non-consumable one-time products.

If the application uses only consumable one-time products, this step can be skipped because one-time products not included in the list are treated as consumable.

Subscriptions do not need to be added to the list. They are acknowledged but never consumed.

Why does a Product Details query return an empty result?

Check that:

  • The Product ID exactly matches the value in Google Play Console.
  • The selected Product Type is correct.
  • The product is active and available to the current testing configuration.
  • The package name matches the application in Google Play Console.
  • The installed application is eligible to use the configured products.
  • Google Play Billing has been initialized successfully.

An In-App Product queried as a Subscription, or a subscription queried as an In-App Product, will not return the expected result.

Why is the Offer Token empty?

The simplified Product Details fields use the first available purchase option.

An Offer Token may be empty when the selected one-time purchase option does not require one.

For subscriptions and purchase options that provide a token, inspect the complete offer arrays and store the Offer Token from the selected entry.

Do I need an Offer Token to launch a purchase?

Not always.

Leave Offer Token empty when the first available purchase option should be used. The plugin queries the product and selects the first available option returned by Google Play.

Pass an Offer Token when the user selected a specific one-time purchase option, subscription base plan, or subscription offer.

See Product Details for details.

Purchase Flow

Which callback should grant the purchased content?

Grant content only from On Success.

Do not grant content from:

  • On Pending
  • On Canceled
  • On Failure
  • On Completed from pending purchase processing

For permanent unlocks, subscriptions, or consumable items, use the returned Product ID to determine what should be granted.

Why did On Pending trigger instead of On Success?

On Pending means Google Play has created the purchase, but the payment has not completed.

This can happen when the payment requires additional time or action.

Do not grant content while the purchase remains pending. The purchase may later change to the purchased state and be processed through the original purchase flow or Pending Purchases.

Why did On Canceled trigger instead of On Failure?

On Canceled is used when the user closes or cancels the Google Play purchase interface.

This is a normal user action rather than a technical purchase error.

Use On Failure for errors such as unavailable products, Billing Client problems, invalid configuration, or acknowledgement failures.

Can several purchase flows be launched at the same time?

No.

The plugin allows only one active purchase flow at a time.

If another purchase is launched while one is already active, the new request returns a failure.

Wait for the current purchase to finish, become pending, be canceled, or fail before starting another purchase.

Why can a non-consumable product not be purchased again?

A non-consumable product remains owned after it has been acknowledged.

Google Play prevents the same account from purchasing the same owned non-consumable product again.

Use the ownership functions to restore access in future sessions.

Why can a consumable product be purchased repeatedly?

The automatic purchase flow consumes consumable one-time products after a successful purchase.

Consumption removes the current ownership and allows Google Play to sell the same product to the account again.

Pending Purchases

Does Process Pending Purchases return purchases that are still pending?

No.

Process Google Play Pending Purchases processes purchases that were previously pending and have since changed to the purchased state.

Purchases that are still waiting for payment are not acknowledged and do not produce On Success.

When should Process Pending Purchases be called?

Call it after Google Play Billing has initialized successfully.

For one-time products, configure the non-consumable Product ID list first.

The function processes one Product Type per call, so call it separately for In-App Product and Subscription when both are used.

Why can On Success or On Failure be called several times?

The function may find several completed purchases during one query.

On Success is called separately for each purchase that was acknowledged successfully.

On Failure may also be called separately for each purchase that could not be processed.

Use the returned Product ID to identify the affected purchase.

What does On Completed mean?

On Completed means the complete processing request has finished.

It is called once after all recovered purchases have produced their On Success or On Failure callbacks.

It does not mean that every purchase was successful.

It is also called when no completed pending purchases are found.

Ownership

Why is a consumable product not returned as owned?

A consumable product is removed from ownership after successful consumption.

Save granted consumable content, such as virtual currency or energy, in the application's own persistent data or backend system.

Ownership functions are intended for non-consumable products and subscriptions.

What is the difference between Query Owned Purchases and Is Product Purchased?

Query Google Play Owned Purchases returns all acknowledged purchases currently owned for the selected Product Type.

Is Google Play Product Purchased checks one specific non-consumable Product ID and returns a boolean result.

Use the query function when restoring several products. Use the single-product function for a simple ownership check.

Why can an ownership check return false even when the product was purchased?

A false result can also be returned when:

  • Google Play Billing is not ready.
  • Google Play cannot complete the ownership query.
  • The purchase is still pending.
  • The purchase has not been acknowledged.
  • A consumable purchase has already been consumed.
  • The wrong Product ID is being checked.

Process completed pending purchases before restoring ownership.

Does Is Subscription Active provide the expiration date?

No.

The function checks whether Google Play currently returns the specified acknowledged subscription as owned.

It does not provide detailed subscription expiration information or server-side validation.

Manual Purchase Flow

Should a consumable purchase be acknowledged before it is consumed?

No.

For a consumable one-time product, call Consume Google Play Purchase.

Consumption fulfills the required purchase confirmation and allows the product to be purchased again.

Do not call both Acknowledge Google Play Purchase and Consume Google Play Purchase for the same consumable purchase.

What happens if a completed purchase is not acknowledged or consumed?

Google Play requires completed purchases to be processed.

A completed non-consumable product or subscription must be acknowledged. A completed consumable product must be consumed.

Purchases that remain unprocessed may be refunded and revoked by Google Play.

When should the manual purchase flow be used?

Use it only for advanced integrations that need direct control over acknowledgement or consumption.

Typical cases include:

  • Backend purchase validation.
  • Server-side content delivery.
  • Custom entitlement systems.
  • Internal processing that must complete before acknowledgement.
  • Manual control over when consumable products are consumed.

Use the standard automatic Purchase Flow for most projects.

Testing and Production

Can purchases be tested with an application installed directly from an APK?

Yes, when the Google account is configured as a license tester and the package name matches the application configured in Google Play Console.

For normal pre-release validation, use a Google Play testing track and install the application through the tester opt-in link.

See Testing for the recommended setup.

Why does the Google Play purchase interface not open during testing?

Check that:

  • Billing initialization completed successfully.
  • The Product ID and Product Type are correct.
  • The product is active and available.
  • The package name matches Google Play Console.
  • The testing account is correctly configured.
  • The application is installed through an eligible testing setup.
  • No other purchase flow is already active.

Also check the failure callback and Android logs for the returned response code and error message.

Why is a test product unavailable?

The product may be unavailable when:

  • It has not been activated in Google Play Console.
  • The Product ID is incorrect.
  • The wrong Product Type is selected.
  • The application package name does not match.
  • The tester has not joined the correct testing track.
  • The product or offer is not available for the tester's region or account.
  • Google Play Console changes have not finished propagating.

Can purchases be tested with a production Google account?

Use a Google account configured as a license tester during development.

Users in a testing track who are not license testers may be charged normally.

Confirm the purchasing account in the Google Play purchase interface before completing the transaction.

What should be checked before publishing?

Before releasing the application:

  1. Verify that the package name matches Google Play Console.
  2. Confirm that every Product ID and Product Type is correct.
  3. Activate the required one-time products, subscriptions, base plans, and offers.
  4. Configure every non-consumable one-time Product ID in the plugin.
  5. Test successful, canceled, failed, and pending purchases.
  6. Test ownership restoration after restarting the application.
  7. Confirm that consumable products can be purchased again after consumption.
  8. Confirm that non-consumable products remain owned.
  9. Remove test-only purchase logic and debug output.
  10. Upload the final AAB and test it through Google Play before production release.
